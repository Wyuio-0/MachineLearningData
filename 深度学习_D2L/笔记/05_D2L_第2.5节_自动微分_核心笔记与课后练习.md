## 一、为什么需要自动微分（Automatic Differentiation）？

在深度学习中，训练模型的核心就是根据损失函数对模型参数求导（梯度下降）。求导通常有三种方式：
1. **符号求导（Symbolic Differentiation）**：像 Mathematica/SymPy 一样推导代数表达式。对于深层复杂网络，公式极易发生“表达式膨胀（Expression Swell）”，计算极其昂贵且无法应对动态控制流。
2. **数值微分（Numerical Differentiation）**：利用有限差分极限 $\frac{f(x+h) - f(x)}{h}$ 逼近。每计算一个参数的偏导就需要进行一次前向传播，对于百万/亿级参数的模型开销是灾难性的，且存在数值舍入误差。
3. **自动微分（Automatic Differentiation, AD）**：
   - **机制**：通过构建**动态计算图（Computational Graph）**，在前向传播时记录每一个操作节点，反向传播时根据微积分的**链式法则（Chain Rule）**从输出反向传递梯度。
   - **优势**：计算精准（达到机器精度）、计算开销与前向传播同阶（时间复杂度极低）、完美支持原生 Python 循环和分支！

## 二、自动求导四大核心机制与代码范式

### 2.1 机制一：梯度追踪与内存复用
```python
import torch

# 1. 创建张量并开启梯度追踪
x = torch.arange(4.0, requires_grad=True)

# 2. 前向计算标量目标 y = 2 * x^T * x
y = 2 * torch.dot(x, x)

# 3. 反向传播计算梯度
y.backward()

# 4. 访问梯度结果
print("x.grad:", x.grad)       # tensor([ 0.,  4.,  8., 12.])
print("验证 4*x:", x.grad == 4 * x)  # tensor([True, True, True, True])
```
> **设计哲学**：
> - `x.grad` 预先分配好内存，其形状与 `x` 严格一致；
> - PyTorch 不会在每次更新参数时分配新内存，从而避免训练过程中成千上万次迭代耗尽系统内存。

---

### 2.2 机制二：梯度的累积效应与必须“手动清零”
* **核心现象**：默认情况下，PyTorch 执行 `backward()` 会将新计算出来的梯度**累加**到 `x.grad` 中（即 `grad += new_grad`），而不是覆盖！
* **设计意图**：这在计算多个数据集的小批量累积梯度、或者多个损失函数的梯度之和时非常有用。
* **致命陷阱**：在训练神经网络时，如果每一个 batch 更新参数前不清除上一步的梯度，梯度会越积越大导致训练发散！
```python
# 清除旧梯度（就地操作 zero_）
x.grad.zero_()

y = x.sum()
y.backward()
print("新梯度:", x.grad)  # tensor([1., 1., 1., 1.])
```

---

### 2.3 机制三：非标量（向量/张量）的反向传播
当输出 $y$ 不是标量（如 $y = \mathbf{x} \odot \mathbf{x}$ 是向量）时，数学上的导数是一个矩阵（雅可比矩阵 Jacobian Matrix）。但在深度学习中，损失（Loss）最终必须是一个标量。

* **直接调用 `y.backward()` 报错**：
  `RuntimeError: grad can be implicitly created only for scalar outputs`
* **正确做法**：必须对非标量求和（转化为标量）后再反向传播：
```python
x.grad.zero_()
y = x * x

# 方式 1（最常用）：先求和转为标量损失
y.sum().backward()
print(x.grad)  # tensor([0., 2., 4., 6.]) 等价于 2*x

# 方式 2：传入权重向量（向量-雅可比积 VJP）
# y.backward(torch.ones(len(x)))
```

---

### 2.4 机制四：计算分离（`.detach()` 冻结梯度流）
有时我们需要将某些计算从计算图中剥离，让梯度不向后流经该节点（将其视为常数）：
* **应用场景**：迁移学习中冻结 Backbone 特征提取层、GAN 对抗训练中交替冻结生成器与判别器、强化学习中目标网络（Target Q Network）参数更新。

```python
x.grad.zero_()
y = x * x
u = y.detach()  # u 拥有与 y 相同的值，但从计算图中脱离（不记录求导历史）

z = u * x
z.sum().backward()

# 因为 u 被视为常数，对 z = u*x 求关于 x 的导数结果就是 u（而不是 3*x^2）！
print(x.grad == u)  # tensor([True, True, True, True])
```

---

### 2.5 机制五：Python 动态控制流求导（Define-by-Run）
即使函数中包含了复杂的 Python 原生 `while` 循环、`if-else` 分支，PyTorch 会在每次前向传播时根据实际执行路径**动态构建计算图**，并精准反向求导：

```python
def f(a):
    b = a * 2
    while b.norm() < 1000:
        b = b * 2
    if b.sum() > 0:
        c = b
    else:
        c = 100 * b
    return c

a = torch.randn(size=(), requires_grad=True)
d = f(a)
d.backward()

# 因为该控制流在局部是分段线性的（d = k * a），所以导数必定恒等于 d / a
print("梯度验证:", a.grad == d / a)  # tensor(True)
```

## 三、第 2.5 节 课后练习题全解（1 ~ 5 题）

### 练习 1：为什么计算二阶导数比一阶导数的开销要更大？
* **解答**：
  1. **计算图规模呈乘数级扩大**：计算一阶导数时，计算图的复杂度与前向传播同阶；而计算二阶导数时，需要把“一阶求导过程本身”当作新的计算图（必须设置 `create_graph=True`），然后再对该图求导，操作节点数量显著增加。
  2. **内存与显存消耗激增**：为了二阶求导，前向激活值与一阶梯度图的所有中间张量都必须全部驻留内存，无法在第一次反向传播后释放。
  3. **高阶张量复杂性**：向量对向量求一阶导是雅可比矩阵（二维），求二阶导则是黑塞张量（Hessian Tensor，三维/四维），参数量呈几何倍数暴增。

### 练习 2：在运行反向传播函数之后，立即再次运行它，看看会发生什么？
* **实验与结果**：
  ```python
  x = torch.tensor([2.0], requires_grad=True)
  y = x ** 2
  y.backward()
  y.backward()  # 立即再次运行
  ```
  **抛出报错**：
  ```text
  RuntimeError: Trying to backward through the graph a second time (or directly access saved tensors after they have already been freed).
  ```
* **原因剖析**：
  PyTorch 出于极端的显存优化考虑，默认在执行完一次 `backward()` 后，会**立即自动释放前向计算图的所有中间缓存**！图被销毁后自然无法二次反向传播。
* **解决办法**：若确实需要多次反向传播，首次调用时需显式声明保留计算图：`y.backward(retain_graph=True)`。

---

### 练习 3：在控制流的例子中，如果将变量 $a$ 更改为随机向量或矩阵，会发生什么？
* **实验与结果**：
  - 前向传播中 `b.norm() < 1000` 会计算向量/矩阵的范数，结果依然是标量，`while` 循环正常工作；
  - `if b.sum() > 0` 依然是标量，条件判断正常工作；
  - **但是在反向传播时报错**：因为此时输出 $d$ 是一个向量或矩阵（非标量），直接调用 `d.backward()` 会报 `RuntimeError: grad can be implicitly created only for scalar outputs`！
* **解决方式**：
  必须将反向传播改为标量形式：`d.sum().backward()`。

### 练习 4：重新设计一个求控制流梯度的例子并分析
设计一个包含循环累加与阈值裁剪的分段函数：
```python
def my_control_flow(x):
    total = torch.tensor(0.0)
    for i in range(3):
        if x > i:
            total = total + x ** 2
        else:
            total = total + x
    return total

x = torch.tensor(1.5, requires_grad=True)
y = my_control_flow(x)
y.backward()

# 分析：
# i=0: 1.5 > 0 -> total += x^2 (导数 2x)
# i=1: 1.5 > 1 -> total += x^2 (导数 2x)
# i=2: 1.5 <= 2 -> total += x   (导数 1)
# 理论导数 = 2(1.5) + 2(1.5) + 1 = 3 + 3 + 1 = 7.0
print("控制流导数:", x.grad)  # tensor(7.)
```

### 练习 5：设 $f(x) = \sin(x)$，绘制 $f(x)$ 和 $\frac{df(x)}{dx}$ 图像（不使用解析解 $\cos(x)$，纯靠自动求导）
```python
import matplotlib.pyplot as plt
import numpy as np
import torch

# 1. 构造连续输入并开启梯度追踪
x = torch.linspace(-torch.pi, torch.pi, 200, requires_grad=True)

# 2. 前向传播
y = torch.sin(x)

# 3. 反向传播自动求导（非标量求和）
y.sum().backward()

# 4. 绘图对比（x.grad 必须 detach 移出计算图后转为 numpy）
plt.figure(figsize=(6, 4))
plt.plot(x.detach().numpy(), y.detach().numpy(), label="f(x) = sin(x)")
plt.plot(x.detach().numpy(), x.grad.numpy(), "--", label="df(x)/dx (Autograd)", color="red")
plt.axhline(0, color="gray", linewidth=0.5, linestyle=":")
plt.grid(True, linestyle="--", alpha=0.6)
plt.legend()
plt.title("Function and Its Autograd Derivative")
plt.show()
```
* **实验结论**：通过 PyTorch 的 `x.grad` 绘制出的导数曲线与理论余弦曲线 $\cos(x)$ 严格重合，证明了自动微分的高精度！
